# Wisland x Daozai 合并方案

> 说明：Wisland 后续对外品牌更名为 Ledge。
> 更新时间：2026-11-17  
> 目标：废弃 Xland 主线，以 Wisland 的窗口、绘制和动画架构为主，分阶段迁移 Daozai 功能。

## 一、总体结论

- 最终程序外壳使用 Wisland。
- 岛体、表情、弹簧、贴边、液桥和鼠标交互以 Wisland 为准。
- 设置窗口、时间天气、AI 额度、通知和应用监听逐步从 Daozai 移植。
- 简单网络与 UI 功能使用 Python 实现。
- 邮件、TLS、Windows 凭据、更新安装和客户端监听等复杂模块，必要时保留 Rust sidecar。
- Xland 不再继续开发，只保留为参考实现；代码已推送到远端分支，可随时恢复。

## 二、优先级总览

| 优先级 | 目标 | 结果 |
|---|---|---|
| P0 | 固定 Wisland 基线 | 防止覆盖现有未提交改动，建立可回退分支 |
| P1 | 统一设置界面 | 不再依赖手改 `config.json` |
| P2 | 打包稳定 EXE | 无 Python 环境也能启动 |
| P3 | 定义服务接口 | Daozai 功能可以逐个接入 |
| P4 | 常驻信息与通知 | 时间天气、额度、通知先进入岛 |
| P5 | AI 额度与连接器 | 分服务逐个移植 |
| P6 | 邮件、日历和消息监听 | 复杂后台与凭据能力 |
| P7 | 性能与发布 | 多屏、高 DPI、长时间运行、安装包 |

## 三、P0：固定 Wisland 基线

当前 Wisland 工作区包含较多未提交修改和删除，开始融合前必须先固定基线。

建议步骤：

1. 保留当前工作区快照。
2. 新建迁移分支，例如 `feat/wisland-daozai-merge`。
3. 给 Xland 分支打归档标签，例如 `archive/xland-p0-p1`。
4. 不删除原版 Daozai 仓库和备份目录。
5. 列出 Wisland 当前可用页面、已删除功能和 Daozai 待移植模块。

验收标准：

- 能明确区分 Wisland 当前保留、删除和待移植的功能。
- 后续修改可以单独回退。
- 不再同时维护 Xland 和 Wisland 两套动画主线。

## 四、P1：统一设置界面

### 1. 窗口结构

- 左侧分类导航。
- 右侧滚动设置卡片。
- 底部“取消 / 保存”。
- 独立普通窗口，不挂在透明岛体上。
- 设置窗口关闭后不应导致主程序退出。

### 2. 分类

1. 常规
2. 岛体与停靠
3. 时间与常驻内容
4. 天气
5. 媒体与歌词
6. 通知
7. 热键
8. 翻译
9. 高级
10. 关于

### 3. 常规设置

- 主题：自动、浅色、深色、胭脂、晴空。
- 开机自启。
- 展开方式：悬停展开、常驻展开、长关。
- 是否可穿透。
- 是否参与截图和录屏。
- 全屏时是否隐藏。

### 4. 岛体与停靠

- 停靠边：上、下、左、右。
- 沿边位置。
- 屏幕选择。
- 缩放。
- 展开延迟。
- 收起延迟。
- 毛玻璃刷新率。
- 收起态显示：时间天气、小表情、音乐。
- 表情岛与信息岛自动切换间隔，默认 30 秒。

### 5. 时间与常驻内容

第一版：

- 24/12 小时制。
- 是否显示秒。
- 是否显示天气。
- 是否显示未读点。
- 信息岛包含哪些组件。

后续：

- 时间、天气、AI 额度排列。
- 多账号额度。
- 通知徽标。

### 6. 天气

- 当前城市。
- 保存城市列表。
- Open-Meteo / OpenWeather。
- API Key。
- 更新间隔。
- 测试连接。
- 手动刷新。

### 7. 媒体与歌词

- 自动显示音乐视图。
- 收起态歌词。
- 网易云本地日志。
- 播放器优先级。
- 封面显示。
- 歌词延迟。

### 8. 通知

- Windows 通知读取开关。
- QQ、微信、飞书、企业微信、钉钉。
- 通知预览与隐私遮罩。
- 任务栏闪烁监听。
- 各应用打开路径。
- 未读色点。
- 通知声音。

### 9. 热键

- 展开/收起。
- 剪贴板翻译。
- 剪贴板历史。
- 热键冲突提示。

### 10. 高级

- 打开配置目录。
- 打开数据目录。
- 打开日志。
- 重新加载配置。
- 导入/导出配置。
- 诊断信息。
- 恢复默认设置。

### 11. 保存机制

必须采用以下流程：

```text
读取配置
→ 复制为 draft
→ 用户编辑 draft
→ 校验
→ 原子写入 config.json
→ 发出配置变化信号
→ 主程序动态应用
```

不要每改一个控件就直接写文件。

设置分为两类：

- 立即生效：主题、展开方式、热键、自动轮换、录制可见、通知开关。
- 需要重新定位或重启：缩放、屏幕切换、部分毛玻璃模式。

需要重启的项目必须在界面明确标注。

### 12. 验收标准

- 设置窗口可独立打开和关闭。
- 保存后重新打开值一致。
- `config.json` 损坏时不会崩溃。
- 非法热键、负数间隔、超大缩放值会被校正。
- 保存使用临时文件与原子替换。
- UI 线程不执行网络请求和阻塞磁盘任务。

## 五、P2：Windows EXE

### 1. 推荐方案

优先使用 PyInstaller `onedir`，第一版不使用 `onefile`。

原因：

- PySide6 插件较多。
- Windows Runtime、COM 和音频 DLL 对解包路径敏感。
- `onefile` 每次启动都需要解压，启动慢。
- 崩溃诊断困难。
- 透明窗口启动初期更容易出问题。

### 2. 目录形态

```text
Wisland/
├─ Wisland.exe
├─ _internal/
├─ config.json
├─ models/          # 可选，不随默认包携带大模型
└─ data/
```

### 3. 打包内容

必须显式处理：

- PySide6 插件。
- Windows 平台插件 `qwindows.dll`。
- `winrt` 运行库。
- `pycaw`。
- `comtypes`。
- `httpx`。
- `SoundCard`。
- `sherpa-onnx`。
- 图标字体。
- 应用图标。
- `config.example.json`。

默认不携带：

- 630 MB 实时字幕模型。
- 日语词典。
- 用户配置。
- 用户日志。
- 用户剪贴板历史。
- 用户凭据。

### 4. 数据目录

安装版建议：

- 配置：`%APPDATA%\Wisland`
- 缓存：`%LOCALAPPDATA%\Wisland`
- 日志：`%LOCALAPPDATA%\Wisland\logs`
- 模型：首次使用时下载

便携测试版可以读取 EXE 同目录，但正式安装版不要写入 `Program Files`。

### 5. EXE 验收

- 没有安装 Python 的机器能启动。
- 双击不弹控制台。
- 托盘图标和菜单正常。
- 单实例锁正常。
- 开机自启使用当前 EXE。
- 设置窗口能打开。
- 日志路径正确。
- 退出后无残留进程。
- 启动失败时能显示可理解的错误。

## 六、P3：建立 Daozai 接入边界

### 1. Python 直接实现

- 天气。
- 时间。
- 简单 HTTP 额度查询。
- 通知显示。
- UI 设置。
- 本地 JSON 数据。

### 2. Python 服务线程

- 本地文件监听。
- 剪贴板。
- 媒体状态。
- 任务栏闪烁。
- 系统托盘。
- 简单 IPC。

### 3. Rust sidecar

- IMAP 邮件。
- CalDAV / Exchange。
- Windows Credential Manager。
- 多账号安全登录。
- 自动更新和安装。
- 高稳定性客户端窗口监听。
- 长时间 TLS 会话。

sidecar 使用命名管道或本机 `127.0.0.1` 随机端口。协议建议使用 JSON lines，每条消息带版本和请求 ID。

## 八、主要重难点

### 1. 黑屏不一定自动消失

Wisland 仍涉及 Qt 透明窗口、Windows 分层、后台截图毛玻璃、DWM 合成和多显示器 DPI。必须保留关闭毛玻璃的兼容模式。

### 2. 设置即时应用

切换停靠边、缩放、主题和穿透时，容易出现窗口跳到旧屏幕、命中区域与画面不一致、设置窗口抢焦点等问题。

应将运行时应用拆成：

- `apply_appearance`
- `apply_geometry`
- `apply_input_mode`
- `apply_capture_mode`
- `apply_hotkeys`

### 3. PyInstaller 动态依赖

最容易出错：

- Qt 平台插件缺失。
- `winrt` DLL 路径失效。
- `pycaw` / `comtypes` 初始化失败。
- `SoundCard` 找不到音频后端。
- 动态导入页面被裁掉。
- frozen 后根目录与数据目录错误。

### 4. 线程模型

Qt 控件只能在 GUI 线程更新。天气、邮件和额度刷新必须通过 Signal 回传。

### 5. 凭据和数据迁移

需要处理：

- 凭据名称兼容。
- 配置格式升级。
- 旧配置备份。
- 迁移失败不破坏源数据。
- 日志不输出密码、Cookie、Token 和验证码。

### 6. 长时间稳定性

必须测试：

- 24 小时运行。
- 睡眠唤醒。
- 网络断开重连。
- 多显示器切换。
- 高 DPI。
- 全屏游戏。
- 设置窗口反复开关。
- 客户端反复启动退出。

## 九、易错点

1. 不要一边迁移一边继续开发 Xland。
2. 不要在 Wisland 主分支直接堆 Daozai 全部代码。
3. 不要让设置控件直接修改全局配置。
4. 不要使用 PyInstaller `onefile` 作为第一版正式包。
5. 不要把用户配置和日志写进 `Program Files`。
6. 不要把实时字幕大模型塞进基础 EXE。
7. 不要从 Python 业务线程直接操作 Qt 控件。
8. 不要让 Daozai 自身通知再次被监听成新通知。
9. 不要把网络检测失败直接当成断网并覆盖正常表情。
10. 不要先移植邮件和日历时再决定 sidecar 架构。
11. 不要只测开发机，要测没有 Python 的 Windows 环境。
12. 不要在未备份 Wisland 未提交改动前做大范围重构。

## 十、建议执行顺序

1. 固定 Wisland 当前工作区，建立迁移分支。
2. 完成统一设置窗口。
3. 完成设置草稿、校验、原子保存和运行时应用。
4. 加入右键菜单和托盘的“Wisland 设置”入口。
5. 做 PyInstaller `onedir` 打包脚本。
6. 在干净环境验证 EXE。
7. 定义 Daozai 服务接口。
8. 接入时间、天气、通知和 AI 额度摘要。
9. 移植 Daozai 设置页面。
10. 按服务逐个接入 AI 额度。
11. 决定邮件、日历、凭据是否转 Rust sidecar。
12. 完成安装器、更新、诊断和长时间稳定性测试。

## 十一、最优先事项

**最优先：设置界面和运行配置。**  
**其次：EXE 打包。**  
**最后：逐步接入 Daozai 功能。**
